## Root cause and correction

The old verifier reproduces `HOLD more_than_one_official_source_url` on the
committed data. In the `vpcp-vi:220065` bibliography row, one anchor is the exact
official `docid=220065` permalink; another is internal `record/5646.html`.
The parser incorrectly classified both as official URLs. This is a false
conflict, not two source publications.

The parser now tracks the optional internal explanation separately. Its path
must match an admitted provenance/article binding with the same exact identity,
family, official URL, content hash, relevance and published QA. VPCP additionally
requires positive independent QA and the current bibliographic metadata digest.
No title/topic/date similarity matching is used. A second official anchor, even
an identical one, a repeated internal explanation, a different official URL,
conflicting source identity, changed version or unadmitted path remains held.
The result remains seven bibliographic/link rows; no renderer or grouping rule
is changed.

The ordinary Daily now runs the existing SQLite/HTML/gh-pages/HTTPS gate after
deployment and before its success marker, under the existing Vietnam admission
flag. HTTPS retries are bounded to three reads; failures exit nonzero. This
restores verification that otherwise lives only on the retired public collector.
It does not certify private cycle health.
