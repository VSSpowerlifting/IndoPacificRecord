What each result means

Every result a collection can record has a plain meaning. They are translated, not merged: two results that both produce zero records can mean opposite things, which is why seventeen of them are kept apart.

Every result and its meaning
What each result means. An empty return has more than one cause and they are not interchangeable.
ResultMeaning
Collected
ok		 Reached the listing and stored new items.
Nothing published
ok_no_publications		 Reached the listing; it carried nothing new. This is healthy.
Nothing new
ok_all_duplicates		 Reached the listing; everything it offered was already in the archive. This is healthy.
Nothing relevant
ok_all_filtered		 Collected fine; nothing met the topic filter.
Not implemented
not_implemented		 Configured, but no working collector exists yet. It contributes nothing by design — and is reported every run so it cannot be mistaken for a healthy source.
Disabled
skipped_disabled		 Configured but switched off.
Could not reach
listing_failure		 The listing could not be retrieved or parsed. The empty result is a fault, not silence.
Access refused
auth_failure		 The source refused access — a login wall, or a refusal returned to an honestly identified collector. Nothing was collected, and nothing was done to defeat it.
Challenge required
access_challenged		 The publisher's edge asked for a browser challenge instead of serving the document. The site is up and the request was well formed — this collector simply is not being served that page. The item is recorded so the gap is visible; the challenge is not solved, retried, or worked around.
Timed out
timeout		 The request ran past its time limit. Whether the source had anything to offer is unknown.
Redirected away
disallowed_redirect		 The request was redirected outside the source's declared domains and was not followed.
Unexpected format
unexpected_content_type		 The response was not the document type the source declares. A challenge page served in place of a listing arrives this way.
Refused as oversized
oversized_response		 The response exceeded the size ceiling and was refused unread. No partial content was kept.
Could not retrieve documents
fetch_failure		 The listing was reached, but the documents it named could not be fetched. Items exist that we do not hold.
Could not read
extraction_failure		 Pages were fetched but nothing usable was parsed — usually the source changed its markup.
Collected, not analyzed
analysis_failure		 Collection succeeded and the records are stored; the analysis step failed for them. The record is intact.
Collector error
adapter_error		 The collector raised an unexpected error. Deliberately kept distinct from the specific failures above so an unclassified crash is never absorbed as one of them.
Unknown source
unknown_source		 A source was requested that no desk manifest declares. This is a configuration fault, not silence.
Storage transaction failure
storage_failure		 The collected batch could not be committed to storage as a single transaction, so the attempt was rolled back in full. Nothing from it was partially saved, and any previously stored records for this source are unaffected.

Refusals are respected

When a source refuses an honestly identified collector, by a login wall, a redirect off its own domains, or a challenge page served in place of a listing, the refusal is recorded as the result and collection stops there. No browser impersonation, no challenge solving, no proxying. An institution that wants to refuse this collector must be able to recognise it and say so, and defeating a refusal would destroy the capability that rule protects.

Why the gaps are published

An archive with undisclosed holes cannot be cited safely. Anyone using this archive to argue that an institution went quiet during one of these windows would be wrong, and would have no way of knowing.
