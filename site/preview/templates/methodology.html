How a record is collected

Each source is declared in advance, with its institution, its language, the pages where it lists new items and how often it is expected to publish. A scheduled collection visits each of those pages, fetches the items, extracts their text, removes duplicates and stores the original with its details. Every source gets an explicit result each time, even when it returned nothing; those results are on Coverage.

Each record keeps the address it was retrieved from, the institution that published it, the publication date the source states, the time of retrieval and a content hash computed once, when the record is first stored. A record's identifier never changes. Two items with the same title stay two records: official institutions reuse titles for distinct events, and merging by title would erase the difference.

Original text, extracted text, machine translation, machine labels and human analysis are five separate layers, and they are labeled separately wherever they appear.

What a machine does

Language models check each record for relevance, translate it and summarize it. The model and the prompt version are recorded for each record. A machine translation is always shown as a translation beside the original, never in place of it. Machine classifications are labeled Model-flagged, never “significant”.

Machine output is not reviewed by a human and can be wrong. The original is always the authority for what was published.

What a person does

Human-controlled analysis is published as an issue or a Brief, under Briefs. It cites the records it rests on. It is interpretation, and it is labeled as such.

Significant and Routine describe an editor's judgment of a weekly edition. They are separate from the machine's record-by-record Model-flagged classifications.

No analytical judgment here carries a confidence number. No calibration method exists, so none is offered.

How current this is

The site reports three dates, because they are three different facts and they come apart exactly when it matters. When a model provider fails, collection keeps running while analysis stops, and a single “last updated” line would have to pick one story to tell.

Records last collected {{ freshness.records_last_collected or 'not measured' }}
The newest document actually stored. Collection runs daily and is the part least likely to be interrupted.
Analysis last produced {{ freshness.analysis_last_produced or 'not yet recorded' }}
The newest date on which any record was analyzed. It says when analysis last ran. It does not say that every record up to that date has been analyzed. How many are analyzed, and how many are records awaiting screening, is counted in the Guide to the records.
Last full update {{ freshness.last_full_update or 'not yet recorded' }}
The last time everything finished, publication included. A collection that fails part-way never records one, so this date can sit behind the other two. When it does, the difference is the outage.

Any of the three may read not measured or not yet recorded. That is a real state: older collections did not record it, and it is printed as it is, not filled in with a plausible substitute.

How evidence is labeled

Every label belongs to one of three layers: the source record, machine output, or human-controlled analysis. Every page marks the layer the same way.

Source record
The item as published, with its original language, canonical link and retrieval time.
Official claim
An assertion by the publishing institution. It is never presented as established fact.
{# id="model-flagged": the address The PLA Watch pages link to as "How flagging works" (pla-watch-post.html, pla-watch-archive.html). #}
Model-flagged
A machine classification, always marked as not reviewed by a human.
Machine translation
An English rendering of a record's title, or of its full text where the source allows, produced by software and shown beside or linked to the original, never in place of it. Not reviewed by a human.
Machine-generated headline
An English headline written by software for some Vietnamese records. It is not a translation of the source title. Not reviewed by a human.
Machine summary
A software reading of a record's stored text. It is a separate output from the title's translation and is labeled separately. Not reviewed by a human; a reading of what was published, not a verification of it.
Human-controlled analysis
An issue or a Brief written under human control, citing the records it rests on. Some pages shorten the label to Analysis.

What a record can support

A record supports

  • That a named institution published a specific item on a specific date.
  • That we retrieved it at a specific time, and what the original text was.
  • Whether a collection reached a configured source, and whether this project stored items from it. It cannot establish everything that source published.

It does not support

  • That an institution believes what it published.
  • That a described capability exists, or that an announced event occurred.
  • That coverage is comprehensive.
  • That a machine summary or translation is accurate without human review.

Known limits

  • Gaps in collection are listed on Coverage and are not smoothed over.
  • Some records are collected but not yet analyzed; they are counted, not hidden.
  • An enabled source can return no new records or fail to collect; the latest result for each source is published on Coverage.
  • Desks that do not collect show no record count. Zero would say the record was checked and found empty; the truth is that no record exists to check.
  • The letter beside each source on Sources describes its position, not its truthfulness. An A source is closer to the institution that speaks; it is not more likely to be accurate.
